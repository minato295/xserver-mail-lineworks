# メール通知の障害処理改善

対象は公開 main ee6ce36 の再レビューで確認した不具合。修正・公開・本番反映は既存のユーザー承認の範囲で進める。実際のLINE WORKS・メールによるテストは行わない。

## 方針

1. ErrorReporterはLINE WORKSへ送らない。配信の失敗そのものをhealth monitorへ記録し、管理者宛ての日本語メールで知らせる。復旧の根拠は通常メール通知の成功のみ。
2. health状態と通知メールの送信状況を分離する。sendmailが失敗してもdegradedを保存し、保留通知は次の観測で再試行する。既存schema v1を読み取り移行でき、管理CLIの診断も対応する。ロック、0600、所有者、HMAC、並行観測順序の検証を維持する。
3. 内部例外は本文・アドレス・URL・例外メッセージ・引数を記録しない。処理段階、標準例外種別、リポジトリ内の発生ファイル名と行番号のみprivate領域へ記録し、原因調査を可能にする。
4. 公開資料の実環境パスをexampleへ変更し、公開チェックを拡張する。履歴を書き換える破壊的操作はしない。
5. 重複排除の保存上限を守り、旧版が作成した上限超過の期限切れ状態を安全に回復させる。
6. 未送信分はprivate領域へ永続化する。保存上限・保持期間・排他制御を設ける。自動再送を本番で起動して作業中に通知しない。送信結果不明または部分送信は明示的に区別し、無条件の全件再送を避ける。運用者が一覧を確認して再送できる経路を提供する。

## 検証と配備

失敗の再現テストを先に追加し、ネットワーク境界をモック化して検証。既存テストと公開チェック、独立レビューを通す。GitHubへ反映後、既存の安全なFTPS/SSH配備・読み戻しで本番反映を検証する。既存のローカルmainの未コミット変更には触れない。
